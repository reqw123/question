# 技術債與架構觀察（2026-08）

這份文件記錄一次跨專案（`desktop-pet`、`lib`、`multi`）協作時觀察到的架構取捨與技術債，不是某個單一決定的 ADR，是「目前現況值得記住的優缺點」快照，供之後評估要不要投入時間處理時參考。之後如果處理掉某一項，直接在該項下面補一行「已於 YYYY-MM-DD 處理，見 commit/ADR」即可，不用整份改寫。

## 做得好、值得維持的地方

- **決策有留痕**：`docs/adr/`、`docs/specs/`、根目錄 `CONTEXT.md` 統一詞彙——多數個人專案不會做到這一步，決策原因半年後還查得到。
- **註解記錄「踩過的坑」而非複述程式碼**：例如 `desktop-pet/main.js` 裡「`L2D` 是頂層 `const` 不是 `window` 屬性，`executeJavaScript` 裡不能寫成 `window.L2D`」「情境存檔沒加 `await` 會造成競爭條件」這類註解，是除錯後才寫得出來的內容，遇到同樣狀況能直接省掉重新踩坑的時間。
- **風險操作一致地做二次確認**：清 API key、清對話記憶、開啟 CLI 免確認模式、清本機快取，統一走同一套確認流程，不是各自寫一套。

## 值得留意的技術債

### 1. 跨檔案共用變數靠全域作用域，沒有模組系統

`multi/`、`lib/` 這批檔案透過 `<script>` 標籤載入順序、靠裸露的頂層 `const`/`function` 跨檔互相呼叫（例如 `lib/live2d.js` 的 `L2D`、`lib/shuffle.js` 的 `shuffleArray`、`multi/multiplay.js` 的一整組 `MP_*` 常數）。

**影響**：靜態分析工具在這個模式下幾乎失效——用 ESLint 掃「未使用變數」時，41 個候選裡有 37 個是假警報，因為工具看不到跨檔的全域用法。這代表死碼偵測、IDE 自動重構、「看起來沒用到就刪」的信心，在這個架構下都打對折，隨檔案數增加會越來越難放心刪東西。

**現況判斷**：小規模、單人維護尚可接受；若檔案數/貢獻者持續增加，建議優先處理。

### 2. `desktop-pet/main.js` 職責過多（~1467 行，8 類職責）

同時扛 app 生命週期、5 個子視窗的開關管理、角色/模型狀態管理、AI 對話管線調度、設定持久化、對外控制伺服器（給 `desktop-pet-web` 用）、風險操作確認——幾乎任何新功能都要回來改這支檔案，是專案裡變更耦合最高的熱點。

**建議方向**：依職責拆成 `windows/*.js`（各子視窗）、`ipc/*.js`（各功能的 IPC handler），`main.js` 只留 app 生命週期與組裝邏輯。不急迫，但檔案只會越長越難改。

### 3. 全域快捷鍵曾造成系統層副作用（已修復，記錄設計教訓）

情境觸發原本綁裸的 `num1`~`num9`（`globalShortcut.register`），這是作業系統層級攔截，只要桌寵開著，數字鍵盤在任何其他程式（Excel、小算盤等）都會被吃掉。已於本次對話修正為 `Control+Alt+num1`~`num9`（見 `desktop-pet/main.js` 情境快捷鍵註冊段落、`desktop-pet/index.html` 提示文字）。

**教訓**：用 Electron `globalShortcut` 前要先確認選用的按鍵組合平常操作會不會撞到，尤其是常駐背景執行的 app，F 功能鍵風險比一般字元鍵低很多。

### 4. 沒有嵌入開發流程的自動化檢查

目前沒有 lint（JS/TS）或靜態檢查（Python）跑在提交前或 CI 上，這次要掃「多餘變數」得臨時裝 ESLint/pyflakes 才查得出來。品質檢查目前完全依賴「想到才手動查」，不是持續性的把關。

**建議方向**：至少幫 `desktop-pet/`（有明確 CommonJS 模組邊界）加一份輕量 `eslint.config.mjs`（只開 `no-unused-vars` 等低誤判規則），`tools/*.py` 加 `pyflakes` 或 `ruff` 到習慣性執行的腳本裡。`multi/`、`lib/` 的全域 script 模式因為第 1 點的限制，lint 效益有限，可以先跳過。

## 優先順序建議

若專案規模不再擴大（維持個人自用），現況可以接受，不用主動處理。若之後功能持續疊加、或考慮找人一起維護，建議順序：**先拆 `main.js`（第 2 點）→ 加基本 lint（第 4 點）→ 視情況評估要不要導入模組系統（第 1 點，改動範圍最大，非必要不建議大動）**。
