# desktop-pet-web 手勢拖曳功能只作用於頁面本地的示範卡片，不橋接到真正的桌寵

desktop-pet-web 已經有一套「網頁按鈕遙控本機桌寵」的機制（`control-server.js`，見「本機控制面板」）。新增手勢辨識功能時，原始需求「透過手勢辨識來操控網頁上的 live2d 角色」在字面上有兩種讀法：操控 Hero 區塊的 Live2DCard 示範卡片（純頁面本地），或是操控真正在使用者電腦上跑的桌寵（透過 control-server 橋接）。這份 ADR 記錄最後選了前者，以及為什麼。

## 決定

手勢拖曳（見 CONTEXT.md）**只作用在 Live2DCard 卡片本身**：

- 手指觸碰卡片內模型輪廓、停留 2 秒選定、跟隨手部移動、比出 Closed_Fist（石頭）放開——全部在瀏覽器頁面內完成，模型移動範圍限制在 **Hero 區塊**邊界內（2026-08-10 修訂，原本是限制在卡片畫布邊界內，見文末修訂記錄）。
- **完全不呼叫 `control-server.js`，不修改 `control-server.js` 或 `desktop-pet/main.js` 任何一行**。
- 跟「本機控制面板」（同一頁面上遙控真正桌寵的既有按鈕）是兩個互不相干的機制，即使桌寵沒有在跑、或 `control-server` 連不上，手勢拖曳照常可用。

## 為什麼不橋接到真正的桌寵

橋接方案（手勢辨識結果透過 control-server 即時搬動真正桌寵視窗的位置）在需求討論過程中曾經是選項之一，最後放棄的原因：

1. **座標系問題不是這次要解的**：鏡頭座標要換算成使用者桌面的絕對螢幕座標，牽涉多螢幕、DPI 縮放，而瀏覽器頁面本身在螢幕上的哪個位置，跟桌寵視窗的位置完全無關——「伸手觸碰」這個手勢對一個可能不在同一螢幕位置的透明桌寵視窗來說，體感上也不直覺。
2. **通訊模式不匹配**：`control-server` 現有的 5 個端點都是一次性 HTTP request/response（觸發一個動作），連續即時的位置串流需要全新的通訊管道（節流 HTTP 或 WebSocket），是完全不同量級的架構工作，不是「新增一個端點」能解決的。
3. **失效隔離的訴求**：這次功能明確要求「即使失效也不影響既有專案系統功能」。只作用在頁面本地的卡片，讓失效邊界縮到最小——手勢辨識/鏡頭權限/WASM 載入失敗，最壞情況就是「卡片不能用手拖了」，不會有任何路徑波及到真正在跑的桌寵或既有的本機控制面板。

## 影響

- 不需要動 `control-server.js`／`main.js`，這次的實作範圍是 desktop-pet-web 內部（新增一個獨立元件 + 對 `Live2DCard.tsx` 的小幅擴充介面），跟桌寵 Electron App 完全解耦。
- 如果之後真的想要「用手把真正桌面上的角色拖著走」，那是全新的一輪設計（座標系轉換、即時通訊管道），不是這次範圍的自然延伸，屆時應該另開 ADR，不要預設可以直接沿用這次的實作。

## 修訂記錄

**2026-08-10：拖曳範圍從「卡片畫布邊界內」放寬到「Hero 區塊邊界內」**

原本的決定是模型移動範圍限制在 Live2DCard 卡片自己的 PIXI canvas 邊界內（見上方「決定」原文）。這條限制本身不是這份 ADR 真正在乎的事——ADR 真正要守住的是「不橋接到真正的桌寵」跟「失效隔離」這兩點，卡片邊界只是當時實作最小可行範圍的自然結果。使用者事後要求放寬到整個 Hero 區塊，評估後確認：

- **不影響本 ADR 的核心決定**：Hero 區塊仍然是純頁面本地（`<section>` 本身 `overflow-hidden`，模型物理上不可能跑出這個區塊），完全不牽涉 `control-server.js`／真正的桌寵，「不橋接」的理由（座標系無意義、通訊模式不匹配、失效隔離）原封不動成立。
- **失效隔離不變**：新增的 `escapeContainer` prop 是 optional 的，沒給的話（或量測失敗）自動退回舊的卡片內 clamp 拖曳，不是「二選一改寫」而是「加了一個可以不给的擴充能力」。
- 實作上是 `Live2DCard.tsx`／`ModelStage` 新增一個「被要求時可以搬到卡片以外畫」的通用能力（`ActiveModelHandle.setEscapeRect()`），不是把畫布本身放大到覆蓋全頁——细節見 `docs/specs/0010-desktop-pet-web-gesture-drag.md` 的「實作備註」。

`docs/specs/0010` 裡「不做自由漫遊整個頁面」那條 Out of Scope 條目對應調整（改為「不做超出 Hero 區塊的漫遊」）。
