# 語音輸入（STT）：OpenAI Whisper API + 點擊切換錄音 + 靜音自動停止

ADR-0002 當時決定 v1 不做語音輸入，只做文字輸入＋語音輸出。這份 ADR 記錄把語音輸入加回來時的架構決定。

**STT 引擎選 OpenAI Whisper API**，不用瀏覽器內建的 `SpeechRecognition`：Electron 沒有內建 Chrome 那組 Google API key，`SpeechRecognition` 在 Electron 環境裡出了名不穩定；也不做 OpenAI Realtime API 那種全雙向即時語音串流——那會整個取代現有「文字聊天＋另外呼叫 TTS」的架構，工程量是完全不同量級，這次維持現有架構、只是把「文字輸入」這一段換成「錄音→轉錄→文字」。

**觸發方式是點擊切換（不是按住說話 push-to-talk）**：點一下 🎤 開始錄音，停止有兩條並行路徑——① 偵測到使用者停止說話（1.5 秒靜音門檻）自動停止；② 使用者自己再點一次 🎤 手動停止。兩者觸發的後續流程一樣：轉錄＋直接送出（不用使用者確認/編輯轉錄結果，跟現有文字輸入的「打字→Enter→送出」是刻意不同的流程，語音輸入本來就是為了比打字快，多一道確認步驟會抵銷這個優點）。錄音中按 Esc 取消（不轉錄、不送出），刻意跟現有「Esc 關閉整個聊天輸入框」的行為分開，避免使用者只是想取消這次錄音卻連整個輸入框都被關掉。

**錄音上限 60 秒**，避免使用者忘記手動停止、忘記靜音偵測失靈時錄音無限進行下去，浪費 Whisper API 額度（照時長計費）。

**麥克風權限在 Electron session 層級直接允许**（`session.setPermissionRequestHandler` 對這個視窗的 media 請求直接放行），不在 Electron 這層再跳一次確認框——跟這個專案「純自用、不多做非必要確認流程」的既有定位一致；Windows 系統層級的麥克風權限提示（設定 → 隱私權 → 麥克風）本來就還在，不會因此完全沒有把關。
