# 即時對話使用雲端 OpenAI API，不用本地模型

桌寵「即時對話」功能要接真正的 LLM 產生回覆。考慮過本地模型（如 Ollama）以求免費、離線、隱私更好，但本地模型的中文對話品質與延遲通常不適合即時語音對話場景，且純自用（見 CLAUDE.md 專案定位）不需要顧慮多使用者的 API 成本分攤問題。因此決定直接接 OpenAI API（聊天用 `gpt-4o-mini`，語音輸出用 OpenAI TTS），不做本地模型的備援路徑。

## 更新：開放 Ollama 本機模型作為可選 provider（見 docs/specs/0005-desktop-pet-ollama-provider.md）

上面「不做本地模型備援路徑」的決定被推翻，但原因（中文對話品質/延遲不適合即時場景）並沒有過時——只是使用者權衡之後，覺得某些情境下（離線、免費、不想再另外付 OpenAI 額度、或單純想試本機模型）值得用品質換這些好處，希望自己能選。

做法不是整個換掉，是**新增一個可選 provider**：

- 設定畫面新增「OpenAI／Ollama 本機」切換，**預設仍是 OpenAI**——原本這句話的判斷（雲端品質/延遲較好）繼續當預設值，不影響任何既有使用者的行為。
- 選 Ollama 之後才會生效，呼叫本機 `http://localhost:11434`（可改）的 `/api/chat`，模型預設 `qwen2.5:7b`（可改成 `qwen2.5:3b` 等其他已下載的模型）。
- 只換「即時對話」這一段文字生成——語音輸入（Whisper STT）跟語音輸出（OpenAI TTS）維持不變，還是走 OpenAI，這兩個沒有被這次决定波及，繼續適用上面原本的 ADR 理由（本機語音辨識/合成的替代方案品質落差更明顯，且不是這次使用者要解決的問題）。

換句話說：這份 ADR 原本的判斷還是對的，只是從「唯一路徑」降級成「預設路徑」，使用者自己知情選擇的話可以換掉。
