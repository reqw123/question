# 破例修改 lib/live2d.js：文字泡泡定位/換行是共用檔案本身的 bug，不是桌寵特有問題

desktop-pet 從一開始就明確定位成「獨立模組，唯讀引用 `lib/`／`live2d_my_like/` 既有資源，不修改任何既有檔案」（見 `package.json` 的 description、`桌面寵物說明.md` 開頭）。這份 ADR 記錄第一次打破這個原則的理由。

## 問題出在哪裡

`lib/live2d.js` 的 `speakFor()`／`_updateSpeechPosFor()`（文字泡泡的顯示與定位邏輯）有三個真正的 bug，不是「桌寵這邊用法特殊」造成的：

1. 泡泡最大寬度用 `paddingLeft` 安全區或「畫面 45% 寬」這種**跟角色實際螢幕座標無關**的猜測值去算，角色站的位置跟這個猜測值對不上時，泡泡會直接跑出螢幕外或被誤判成沒有空間、擠成一行一個字。
2. 泡泡的垂直位置完全沒有邊界檢查——角色站在畫面上緣/下緣，泡泡照樣會算出跑出畫面的 `top`。
3. `word-break:keep-all` 對沒有空白分隔的連續中文句子會讓瀏覽器找不到斷行點，長文字直接橫向撐破 `maxWidth`。

`multi/host.html`／`multi/player.html`（問答遊戲）目前沒有踩到這幾個問題，只是因為遊戲裡的角色位置通常是相對固定、配合 `paddingLeft` 等版面設定調過的——邏輯本身的 bug 一直都在，只是問答遊戲的使用情境剛好沒有觸發。桌寵的角色可以被使用者拖到透明視窗的任何角落（畫面邊角是常態，不是例外），觸發機率高很多，但這不代表這是「桌寵特有的問題」，而是同一個 bug 在不同使用情境下被踩到的機率不同。

## 為什麼不在 desktop-pet 這邊繞過去

曾經考慮過的替代方案：在 desktop-pet 自己的程式碼裡，每一幀量測泡泡的實際位置，發現超出螢幕就強制拉回來——完全不碰 `lib/live2d.js`。

放棄這個做法的理由：

- **治標不治本**：`word-break:keep-all` 這種 CSS 排版問題沒辦法從外部用 JS 事後修正版面已經跑掉的視覺結果，只能改 CSS 定義本身。
- **一定會有閃現的錯誤畫面**：外部修正只能在瀏覽器排版完成之後才量測到問題，中間會有一幀是跑版的，使用者看得到那個瞬間。
- **重工且容易產生兩份邏輯分歧**：定位計算等於要在 desktop-pet 這邊重新實作一次 `_updateSpeechPosFor()` 的邏輯，兩份程式碼日後很容易走鐘走成不一致，維護成本比直接修好源頭更高。

## 決定：直接修 `lib/live2d.js`，但只修真正的 bug

- 只改**排版正確性**（螢幕邊界內、文字正常換行），不改任何跟「桌寵特有需求」相關的行為（生長方向、顏色、動畫節奏這些照舊）——確保這次修改對 `multi/host.html`／`multi/player.html` 只有「原本可能出現的 bug 不會再出現」這一種影響，不會改變任何目前正常顯示的既有畫面。
- 這是目前為止**唯一一次**修改 `lib/live2d.js`，不代表「唯讀引用」這個原則整個作廢——之後除非又遇到同一種「源頭本身有 bug，事後修正治標不治本」的情況，否則繼續維持不修改共用檔案。
- `package.json` 的 description 與 `桌面寵物說明.md` 已經更新，註明這個例外並指回這份 ADR，避免日後看到「不修改任何既有檔案」這句話卻對不上實際的 git 歷史。

見 `docs/specs/0007-desktop-pet-speech-bubble-and-interrupt-fixes.md` 了解實際改了什麼。
