### `skill2`（露西）最終時間軸

這是經過多輪 Console 實測調整後定案的版本：

| 時間 | 內容 |
|---|---|
| 0~1s | 左眼、嘴巴**同時**閉上；頭部同步往左歪（`ParamAngleZ` → 30） |
| 1~4s | 雙層光芒（`Param36/38` 透明度、`Param39/40` 長度）從隱藏**線性**增長到最大——刻意不用 ease 曲線，確保增長過程平穩、看得出來是慢慢變大，不會一出現就衝到最大 |
| 4s | 光芒長到最大，同一刻：雙層轉動開始（`Param33`/`37`，反方向、不同轉速）；腳底雲層/風刃（`Param41/42/43`）、獨立光元素（`Param44~47`）都在這一刻才出現，之前都不運作 |
| 0~10s（全程） | `Param`（懸浮）用三角波在 -30~30 之間快速直線遞增遞減巡迴；`Param23`（左腳）、`Param44~47`（光元素）跟隨 `Param`；`Param9`（肩膀）跟隨 `Param` 但縮放到 -30~0 |
| 8~10s | 所有特效（雙層光芒、轉動、風刃/雲層、光元素）用「凍結當下數值、單調 easeOut 收到 -30」的方式平滑淡出，避免收尾收到一半又冒出來；左眼同時張開回復 |

只驅動這 19 個參數，其餘沒驗證過的維持原本 idle 留下的狀態不受影響。

**設計過程中的幾個關鍵教訓（給以後做其他動作參考）：**
- **成長曲線不要用 `easeOut`**：一開始用 easeOut（先快後慢）做「光芒逐漸增長」，結果變成「一出現就衝一大截」，跟預期的「慢慢變大」完全相反——增長類效果要用線性或 ease-in（先慢後快），easeOut 只適合「快速接近某個值然後停住」這種收尾用途，不適合「從無到有的緩慢展開」
- **host.html 裡角色載入會自動播放 idle 動作、而且它是 Loop:true**，跟我們 Console 手動設的參數會互相覆蓋打架——如果測試時發現角色「卡住」、數值設定看起來完全沒生效，先執行 `model.internalModel.motionManager.stopAllMotions()` 停掉背景一直在跑的 idle 動作，再測
- 淡出（fade out）一定要用「凍結當下數值＋單調 easeOut」，不要用「原始值與目標值線性混合」（後者在還在震盪/擺動的曲線上，淡出淡到一半會因為原始值剛好擺回高點而看起來又冒出來一次）

## 四、F12 開發指令

方法跟 `076/納茲.md` 完全一樣（開 `Live2d-model-master/index.html`，選角色 `077`，用 Parameter 檢查器實測），直接參考那份文件的第四節，把角色/參數 Id 換成這裡列的即可。

播放這次的技能動作：

```js
L2D.play('skill2')
```

在 host.html/player.html 裡用 Console 直接操控參數（先停掉背景 idle 動作再測）：

```js
const model = L2D._c2.model;  // 露西是角色幾就對應 _c1 或 _c2
model.internalModel.motionManager.stopAllMotions();
const cm = model.internalModel.coreModel;
cm.setParameterValueById('Param33', 0);
```

### `chatter`：碎嘴子（快速開合模擬碎碎念）——✅ 已實測確認露西也適用

完整動作定義、設計原理、更正紀錄都寫在 `076/納茲.md` 第五節（`chatter` 是照納茲的需求先寫的，露西沒有另外一份），這裡只記露西專屬的部分：

```js
L2DGesturePlayer.play('chatter')         // 不帶 charKey → 納茲＋露西同時碎念，已實測確認兩人嘴巴都會動
```

能共用同一組 `1`/`0` 數值的原因：納茲、露西的 `ParamMouthOpenY` 都是標準 0~1（見上方第二節的更正紀錄），量尺相同，不需要像原本以為的那樣分別設計兩組數值。

## 六、後續延伸/優化建議

- **`Param34`、`Param35` 還沒驗證**，優先拿去測，量級跟已知特效接近，可能是光粒子的另一個維度
- **還有約 30 個數字參數完全沒測過**，繼續用 Parameter 檢查器逐一驗證
- **跟納茲一樣，特效如果想要更誇張**，天花板可能就是這幾個參數各自的合法範圍上限（多半是 -30~30），真的要更浮誇得靠角色整體 `model.scale` 或疊加 `MagicShotVFX.js`
- 這次「三角波快速巡迴＋多個參數跟隨同一個數值」的手法（`Param`→`Param23`/`Param9`/`Param44~47` 都跟隨同一個 `paramVal`）是一個很省事的技巧：只要抓到一個核心動態，其他相關部位直接跟隨或等比例縮放，不用每個都獨立設計曲線，之後遇到「一群部位要連動」的情境可以直接套用
