# 076（納茲）Live2D 模型筆記

角色：納茲・多拉格尼爾（火焰龍魔導士，Fairy Tail）。這份文件記錄這個角色專屬的 Parameter 對照、既有動作、除錯方式跟後續可以延伸的方向——都是這次實際用 Console 拖滑桿、寫腳本測出來的，不是猜的。

不影響專案既有掃描邏輯：`generate-manifest.js` 只找 `*.model3.json`/`model.json`，不會處理 `.md`，這份文件放在這裡不會被誤認成模型或造成任何載入異常。

---

## 一、模型檔案

```
c_7001.moc3              ← 骨架/網格綁定（二進位，唯讀，不能改）
c_7001.model3.json       ← 檔案清單（含 Motions 註冊）
motions/c_7001.motion3.json  ← 原始待機動作（6 秒，Loop）
motions/skill_02.motion3.json ← 技能動作（12 秒，一次性）
textures/texture_00.png  ← 唯一一張材質貼圖
```

`.moc3` 二進位裡有 16 個 `Rotation` 系列變形器、多個 `Warp` 變形器、101 個 `ArtMesh`、約 15 個 `Part`，還有一個 `Glue__ArtMesh77__ArtMesh72`（黏合兩片網格）。所有 Part/ArtMesh 的名字都是 Cubism 自動流水號（`Part2`、`ArtMesh37`...），**沒有人類可讀的命名**，沒辦法直接從名字反查用途，只能靠拖 Parameter 滑桿實測。火焰效果幾乎可以肯定是靠其中幾個 `Rotation` 變形器持續旋轉騙出來的視覺效果（土炮做法，Live2D 沒有真正流體模擬）。

## 二、已確認的 Parameter 對照表

### 火焰相關（這次的重點，全部實測確認）

| 參數 | 範圍 | 預設 | 作用 |
|---|---|---|---|
| `Param17` | -30 ~ 30 | 0 | 手掌核心火焰的大小/開合。**0 = 全開，往正或負任一端都是縮小/隱藏**（不是一端小一端大，是離開中心點就收起來的顯隱控制，兩端都到頭就是完全消失） |
| `Param18` | -30 ~ 30 | 0 | 同 `Param17`，手掌核心火焰的另一路控制，通常跟 17 一起變、但可以給不同的中繼值做出層次感（這次動作設計裡 17 停在 -15、18 停在 -25） |
| `Param19` | -30 ~ 30 | 0 | 火焰**邊緣**的火苗閃動（不是核心開合，是核心之外的細節閃爍） |
| `Param20` | -30 ~ 30 | 0 | 同 `Param19`，邊緣火苗的另一路，兩個目前都是同步驅動，還沒測出彼此的差異 |
| `Param21`～`Param27`（共 7 個） | 約 -30 ~ 210（實際原始曲線觀察到的範圍，比 17-20 大很多） | -30 | 角色周圍纏繞的**外圍**烈焰（範圍比手掌火焰大很多，可能是不同層級的火焰特效） |

### 身體/其他（實測或高信心標準命名）

| 參數 | 作用 | 備註 |
|---|---|---|
| `Param4`、`Param5`、`Param6` | 整隻手臂的擺動/位置 | 實測確認；`Param6` 這次動作全程固定 30 沒有變化 |
| `Param16` | 圍巾 | 實測確認，跟火焰無關，讓它自然擺動即可 |
| `ParamBodyAngleY` | 身體上下晃 | 實測確認 |
| `ParamBodyAngleZ` | 身體左右晃 | 實測確認 |
| `ParamMouthOpenY` | 嘴巴閉合～張開露牙齒，範圍 -30~30，-30=閉、30=露牙齒 | 注意：跟一般 Cubism 慣例的 0~1 不一樣，這個模型是自訂的 -30~30 |
| `ParamHairFront`／`Side`／`Back` | 前／側／後三層頭髮 | 標準命名，原始 idle 動作裡振幅約 ±18~19 |
| `ParamAngleX`／`Y`／`Z` | 頭部左右轉／點頭／歪頭 | 標準命名，這次動作沒有用到，維持原本 idle 留下的姿勢 |
| `ParamEyeLOpen`／`ROpen` | 左右眼開合（眨眼） | 標準命名，這次動作沒有用到 |
| `ParamEyeBallX`／`Y` | 眼球視線方向 | 標準命名，原始 idle 全程 0，沒用到 |
| `ParamBodyAngleX` | 身體另一軸（推測是側傾或前後，未實測） | 原始 idle 全程 0 |
| `ParamEyeLSmile`／`RSmile`、`ParamBrowLForm`／`RForm`、`ParamMouthForm`、`ParamCheek`、`ParamBreath` | 表情相關，原始 idle 全程 0，可能沒接視覺效果或交給 physics3.json | 未使用、未測試 |

### 完全未測試

`Param`、`Param2`、`Param3`、`Param7`～`Param15`、`Param28`、`Param29` —— 共 12 個，原始 idle 動作裡有數值變化（推測是頭髮/衣物次要擺動鏈，但這個猜測已經在 17~27 這組上被證明不可靠，須實測才能確認）。

## 三、已有動作（`c_7001.model3.json` 的 `Motions[""]`）

| Index | 檔案 | 觸發方式 | 說明 |
|---|---|---|---|
| 0 | `motions/c_7001.motion3.json` | `L2D.play('c_7001')` 或不特別呼叫、`_go` 找不到別名時的退路 | 原始待機動作，6 秒 Loop，呼吸/眨眼/髮絲擺動 |
| 1 | `motions/skill_02.motion3.json` | `L2D.play('skill2')`（檔名對上 `lib/live2d.js` 的 `L2D_ALIASES['skill_02']='skill2'`） | 技能動作，12 秒一次性，見下方時間軸 |

**注意**：`L2D.play('skill')`（不帶數字）現在**沒有對應的檔案**，會觸發 `_go()` 的退路機制，安靜地退回播放 index 0（原廠待機動作）。這是刻意的設計——`skill_01`/`'skill'` 保留給以後真的想做「原廠等級」的動作時再用，目前所有新設計的技能動作一律從 `skill_02`/`'skill2'` 開始編號。

### `skill` 時間軸

| 時間 | 內容 |
|---|---|
| 0~5s | `Param17/18` 從 -30 線性爬升到 -15/-25；`Param5`=30（手臂未抬）；圍巾／身體自然搖擺 |
| 4.5~4.8s | 露牙齒（`ParamMouthOpenY` -30→30） |
| 5~5.2s | `Param5`／`Param4` 快速變 -30（手臂抬起） |
| 5.2~5.4s | `Param17/18` 快速衝到 0（核心火焰全開） |
| 5.4s | `Param19/20` 開始運作（邊緣火苗）；三層頭髮開始 0.5 秒快速晃動 |
| 5.9~8.9s | 三層頭髮緩慢爬升到 30 |
| 0~10s | `Param21~27`（外圍烈焰）全程持續變化；蓄力後身體搖擺幅度/速度加大 |
| 10~12s | 所有火焰參數平滑淡出到 -30，動作結束 |

只驅動這 21 個參數（`Param4/5/6/16~27`、`ParamBodyAngleY/Z`、`ParamMouthOpenY`、`ParamHairFront/Side/Back`），沒涉及的參數（頭部角度、眨眼等）維持原本 idle 動作留下的狀態不受影響。

## 四、F12 開發指令備忘

### 開啟方式

用 `Live2d-model-master/index.html`（要透過 Live Server，不能雙擊開），選遊戲「少女次元」→ 角色 `076`，**先不要點下面的動作按鈕**（不然動作曲線會覆蓋你手動設的值，兩邊打架）。

### Parameter 檢查器（已內建在 `Live2d-model-master/index.html`）

點右上角「🔍 Parameter 檢查器」，會列出目前模型全部參數的即時滑桿，直接拖就能看畫面反應，這是找出「哪個參數控制什麼」最可靠的方法。

### 查一個參數的合法範圍

```js
(function() {
  const cm = curModel.internalModel.coreModel;
  const idx = cm.getParameterIndex('Param17');
  console.log('min:', cm.getParameterMinimumValue(idx),
              'max:', cm.getParameterMaximumValue(idx),
              'default:', cm.getParameterDefaultValue(idx));
})();
```

### 直接設定某個參數

```js
curModel.internalModel.coreModel.setParameterValueById('Param17', 0);
```

### 播放已有動作

```js
L2D.play('skill2')   // 觸發 skill_02（目前唯一的技能動作；'skill' 沒有對應檔案會退回原廠待機動作）
L2D.play('wait')     // 只要模型有對應別名就會播；找不到對應時會退回播放模型第一個可用動作
curModel.motion('', 0, 3)  // 直接指定 group/index 播放（3 = FORCE 優先度，立刻打斷目前動作）
```

### 不重整頁面、回到正常待機狀態

```js
curModel.motion('', 0, 3)  // 重新播放原始 idle，每一幀會自己覆蓋掉手動設定的殘留值
```

或手動把測試用到的參數設回預設值：

```js
(function() {
  const cm = curModel.internalModel.coreModel;
  ['Param4','Param5','Param6','Param16','Param17','Param18','Param19','Param20',
   'Param21','Param22','Param23','Param24','Param25','Param26','Param27',
   'ParamBodyAngleY','ParamBodyAngleZ','ParamMouthOpenY',
   'ParamHairFront','ParamHairSide','ParamHairBack'].forEach(id => {
    const idx = cm.getParameterIndex(id);
    cm.setParameterValueById(id, cm.getParameterDefaultValue(idx));
  });
})();
```

## 五、後續延伸/優化建議

- **還有 12 個參數完全沒測過**（`Param`、`2`、`3`、`7`～`15`、`28`、`29`），可能還有其他視覺效果（例如衣物細節、其他部位特效）沒被發現，用同一套滑桿實測方法可以繼續挖
- **`Param19` 跟 `Param20` 目前是同步驅動、沒有差異化**，可以測測看兩者分開設定時是否有各自獨立的效果（例如控制不同顆粒子/不同方向的火苗），如果有，未來動作可以做出更豐富的邊緣火焰層次
- **`ParamAngleX/Y/Z`（頭部轉動）這次動作完全沒有用到**，如果要做「頭跟著手看火球」的效果，可以加進下一版技能動作，這是原本 8 階段設計裡提到但這次沒實作的部分
- **`skill_02.motion3.json` 檔案約 155KB**，比原始 idle（30KB）大不少，是因為外圍烈焰/邊緣火苗這種持續擺動的參數用了較密集的取樣點去逼近正弦波；如果之後要做更多技能動作、擔心檔案總大小，可以在擺動的部分改用較稀疏的取樣＋接受曲線稍微不那麼精確
- **目前只依賴 Cubism 內建的 `FadeOutTime`／`FadeInTime` 做動作間的自動淡入淡出**，沒有刻意讓 `skill_02` 結尾的每個參數精確對回 idle 動作 t=0 的原始數值；如果之後想要更嚴謹的無縫銜接，可以把結尾（10~12 秒那段）的目標值改成完全對齊 `c_7001.motion3.json` 對應參數的 t=0 數值，而不是統一收斂到 -30
- **`skill_01`/`'skill'` 目前刻意留空**，是保留給「原廠等級」動作用的編號，之後若想再幫納茲做一顆動作，記得從 `skill_03`/`'skill3'` 開始編號，不要佔用 `skill_01`
- **火焰的「變大」有天花板**：實測過 `Param17-20` 的極限就是預設值 0（不能比這更大），如果想要視覺上更誇張的火球，只能靠角色整體 `model.scale`（PIXI 層級）在爆發瞬間放大，或是接上專案既有的 `MagicShotVFX.js` 疊加額外的粒子特效層，不能只靠這幾個 Cubism 參數本身
- **這份文件目前只涵蓋 076（納茲）**，如果之後要對 077（露西）或其他角色做同樣的技能動作，建議比照這次流程：先用 Parameter 檢查器实測，再另外寫一份專屬於那個角色的對照表，不能假設不同模型的參數編號有一樣的用途（例如 077 的 `Param17` 不一定也是控制火焰，每個模型的綁定都是各自獨立在 moc3 裡定義的）
