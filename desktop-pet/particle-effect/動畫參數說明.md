## 🚀 30 秒快速看懂（TL;DR）

> [!TIP]
> - 一個模型只有 `file` 是必填，其餘全部有安全預設值（見下面〈完整欄位對照表〉），可以先什麼都不填，看效果不對再一項項加。
> - 播放模式三選一（可以只選一種，或都不選）：**單幀定格**（預設）／**`animatedIdle: true`**（一直循環播放）／**`periodicAnimation`**（閒置觸發播一次）。`animatedIdle` 跟 `periodicAnimation` **不能同時開**，會互搶同一組 shader uniform。
> - 想知道多段動畫接起來播、每段各分到幾張關鍵幀：看下面〈關鍵幀分配公式〉，帶公式帶例子。
> - 銜接處動作看起來變慢／滑：通常是 `animationFrames` 相對總秒數太少，見〈銜接處變慢怎麼排查〉。
> - 想讓某個動作播快一點/慢一點（不是換動畫，是同一段動畫加速/減速）：`animationSpeed`（`animatedIdle` 用）或 `periodicAnimation.speed`（定時動作用），倍率型欄位，`1` 是原速。
> - 想校正 `scale`/`position`/`rotationY` 這類數字：`Ctrl+Shift+I` 開 DevTools 看 Console，搭配互動模式下的鍵盤微調工具，見〈手動微調 debug 工具〉。
> - 換模型前想先知道包圍盒/動畫清單/顏色，不用臨時寫診斷腳本：`npm run inspect-model -- <檔名>`，見〈換模型前先跑 inspect-model 量測工具〉。

## 🔍 換模型前先跑 inspect-model 量測工具

`sources.js` 新增一個模型（或幫既有 key 換 `file`）之前，先跑這個命令列工具唯讀量測一次，取代每次都臨時寫一次性 Node 腳本診斷的做法（起源：`volibearModel` 那次為了查「粒子沒有確實呈現模型輪廓」的問題，手動寫腳本量出真實包圍盒才發現是幽靈頂點灌水縮放基準，這個工具就是把那次手動診斷的步驟收成常駐指令）。

### 用法

```
npm run inspect-model -- <檔名>
```

- **要在 `desktop-pet` 根目錄（`package.json` 那層）跑**，不是 `particle-effect/` 底下；`--` 是必要的分隔符，告訴 npm「後面這個是要傳給底層腳本的參數」。
- 檔名不用加路徑，固定去 `particle-effect/models/` 底下找（跟 `sources.js` 的 `file` 欄位同一個資料夾）。
- 已經 `cd` 到 `particle-effect/` 底下的話，改用 `node tools/inspect-model.mjs <檔名>`；在根目錄也可以跳過 npm 直接 `node particle-effect/tools/inspect-model.mjs <檔名>`。

只做唯讀量測跟印報告，**不會寫入 `sources.js`**——印出來的數字自己抄過去，或整段報告丟給 Claude 讀，讓它幫忙把新 entry 填好。

### 輸出怎麼讀

| 區塊 | 內容 | 怎麼用 |
|---|---|---|
| mesh 清單 | 每個 mesh 的頂點/三角形數，`[skinned]` 標記有沒有骨架 | 全部都不是 `[skinned]` ＝沒有骨架，`animation`/`animatedIdle`/`periodicAnimation` 這幾個欄位完全用不到，可以整段不寫 |
| 疑似重複部位 | vertexCount + 原始包圍盒幾乎一樣的 mesh 分組 | **純啟發式，僅供參考**——可能是真的重複部位（像 `kaidoModel` 的換臉/換手），也可能只是同一份骨架分材質輸出的正常子網格（像 `volibearModel` 的 Body/Wings/HipBuff），實際性質要自己判斷 |
| 真實包圍盒 | bind/rest pose 下、已過濾退化三角形的包圍盒 | 跟執行期 `computeBounds()` 用同一套演算法，這裡的數字保證跟實際套用後看到的一致 |
| 自動置中縮放會算出的結果 | 等同 `sources.js` 完全不填 `scale`/`position` 時，執行期會自動算出的數字 | **多數情況不用真的貼進 `sources.js`**，印出來只是給你確認 auto-fit 的結果合理（不是 NaN、不是離譜的極端值）；只有想避免 `animatedIdle` 不同姿勢重算 auto-fit 導致觸發時跳一下、或想手動再微調，才需要真的填死 |
| 動畫清單 | 全部動畫 clip 名稱＋秒數，格式已經是可以直接複製貼上的陣列項目 | 挑一段當 `animation`（單幀定格用），或挑一段當 `periodicAnimation.name` |
| 取色 | 材質的 `baseColorFactor` | Node 沒有 `canvas`/`document`，貼圖平均色（`sampleAverageMaterialColor()` 的貼圖路徑）在這裡測不出來，只能看 `baseColorFactor`；材質**沒有貼圖**時這欄位就是實際會生效的顏色，材質**有貼圖**時要等 Electron 裡實際開特效才會看到真正取到的顏色 |

### 量不出來的部分

- **朝向（`rotationY`）**：GLB 沒有「正面朝哪」的語義資訊，工具量不出來，只能開特效實際看一次再手動加這個欄位，或乾脆不管、讓 `idleMotion` 的 `spin` 自轉讓每個角度遲早轉到鏡頭前。
- **該挑哪段動畫當 idle / 該挑哪段當觸發彩蛋**：動畫清單只列出名字＋秒數，語義判斷（哪段像站姿、哪段像必殺技）還是要人看名字自己選。

### 跟其他校正手段的分工

| 手段 | 用途 | 時機 |
|---|---|---|
| `inspect-model` 工具 | 唯讀量測包圍盒／動畫清單／疑似重複部位 | 換 `file` 之後、填 `sources.js` 之前的第一步 |
| auto-fit（`scale`/`position` 不填） | 執行期自動置中縮放，已內建過濾退化三角形（見上表「自動置中縮放」那行） | 多數模型可以直接用，不用手動填死 |
| [手動微調 debug 工具](#-手動微調-debug-工具)（鍵盤） | 畫面上即時試 `position`/`rotationY`/`scale` | auto-fit 效果不理想需要精修，尤其是 `rotationY`（工具測不出朝向）非用這個不可 |

## 📋 完整欄位對照表

每個模型在 `sources.js` 裡的形狀：

```js
someModel: {
  file: '...',        // 必填，models/ 底下的實際檔名
  particle: { ... },  // 選填，取樣校正 + 動畫參數，見下表
  color: [r, g, b],   // 選填，粒子顏色，每個 0-1
  idleMotion: { ... },// 選填，閒置動畫風格，見下表
},
```

### `particle` 底下的欄位

| 欄位 | 型別 | 作用 | 不填時的預設 |
|---|---|---|---|
| `scale` | `[x,y,z]` | 取樣後縮放，跟 `position`/`rotation*` 套用順序固定是**先 scale，再 rotate，最後 translate** | 自動置中縮放（auto-fit，見下方說明） |
| `position` | `[x,y,z]` | 取樣後平移 | 自動置中縮放算出來的置中位置 |
| `rotationX/Y/Z` | 數字（rad） | 取樣後繞該軸旋轉 | `0` |
| `animation` | 字串 或 字串陣列 | 取樣前要先把模型 pose 定格/循環在哪段動畫。陣列格式只有搭配 `animatedIdle:true` 才有意義，見下一節 | 不填 = 用 bind/rest pose |
| `animationTime` | 數字（秒） | **只有「單幀定格」路徑會用到**：把 `animation`（或陣列第一個字串）定格在第幾秒的姿勢去取樣。`animatedIdle`/`periodicAnimation` 兩條路徑都不看這個欄位 | `0` |
| `animatedIdle` | `true`/`false` | 開了 = 走「動畫粒子化」：粒子形狀跟著 `animation` 指定的那段（或那幾段）**一直循環播放**，不是定格單一姿勢 | `false`（單幀定格） |
| `animationFrames` | 數字 | `animatedIdle` 開了才有意義：整條播放序列要烘幾張關鍵幀貼圖的**總預算**，依各段時長比例分配（見〈關鍵幀分配公式〉） | 依總秒數自動算（見下面〈關鍵幀數量自動計算〉），不是固定值 |
| `animationSpeed` | 數字 | `animatedIdle` 開了才有意義：整條序列的播放速度倍率，`2`＝兩倍速、`0.5`＝半速、`0`＝凍結在目前幀不動。跟 `animationFrames`（畫質/內插密度）是兩件事，互不影響 | `1`（跟原始 GLB 動畫真實秒數一致） |
| `periodicAnimation` | 物件 | 「定時動作」：平常維持定格姿勢，閒置滿 `intervalSeconds` 秒才觸發播一次，播完自動退回定格姿勢。**跟 `animatedIdle` 互斥**，見下一節 | 不填 = 沒有定時動作 |
| `periodicAnimation.name` | 字串 或 字串陣列 | 要播哪一段（或哪幾段，依序接續播放）動畫，格式跟 `animation` 一樣 | 必填（有 `periodicAnimation` 才需要） |
| `periodicAnimation.intervalSeconds` | 數字（秒） | 閒置幾秒觸發一次 | `60`（`DEFAULT_PERIODIC_INTERVAL_SECONDS`） |
| `periodicAnimation.frameCount` | 数字 | 分配方式跟 `animationFrames` 一樣，只是這是給觸發動畫這條序列用的獨立預算 | 依總秒數自動算，同一套公式，跟 `animationFrames` 各自獨立計算 |
| `periodicAnimation.speed` | 數字 | 播放速度倍率，用法跟 `animationSpeed` 一樣。⚠️ 填 `0` 會讓觸發動作卡在播放中、永遠不會播完退回定格姿勢（比 `animationSpeed` 的 `0` 多一個「回不去」的副作用，見下面備註） | `1` |

### 模型層級欄位

| 欄位 | 型別 | 作用 | 不填時的預設 |
|---|---|---|---|
| `color` | `[r,g,b]`（0-1） | 粒子顏色 | `[0.55, 0.8, 1.0]`（淡藍色，`DEFAULT_COLOR`） |
| `idleMotion.type` | `'spin'` / `'bob'` / `'swing'` | 完全聚合後的閒置動畫風格：`spin` 連續自轉／`bob` 短距離來回位移（像上下浮動）／`swing` 短距離來回轉動（像左右擺頭，有擺角上限、會轉回去） | `'spin'` |
| `idleMotion.axis` | `'x'/'y'/'z'` | `bob` 決定位移哪個軸、`swing` 決定繞哪個軸擺 | `'y'` |
| `idleMotion.amplitude` | 數字 | `bob` 是位移量、`swing` 是擺角（rad） | 見〈附錄：預設值一覽〉 |
| `idleMotion.speed` | 数字 | 動畫節奏，數字越大動作越快（`spin` 是 rad/s 角速度，`bob`/`swing` 是相位角頻率） | 見〈附錄：預設值一覽〉 |

> [!NOTE]
> **自動置中縮放（auto-fit）**：`scale`/`position` 只要有一個沒填，`particle-sampler.js` 就會自己拿這顆 GLB 的（bind pose）世界座標包圍盒去置中縮放，不用手動猜數字，適合還沒校正過的新模型先求「看得到東西」。

> [!NOTE]
> **`animationSpeed` / `periodicAnimation.speed` 是倍率，不是秒數**：套用位置是 `particle-effect.js` 的 `advanceAnimationPlayback()`／`advancePeriodicAnimation()`，直接乘在每幀的 `delta` 上（真實經過的秒數）再累加，跟 `animationTime`（單幀定格用，見上面說明）完全是兩件事，不要混在一起想。負數會被強制拉到 `0`（`Math.max(0, ...)`）——负的 delta 累加会让播放相位變負，取模/貼圖陣列索引都會壞掉，這裡不支援「倒著播」。`0` 本身是合法值，代表「凍結在目前這一幀」；`periodicAnimation.speed: 0` 要特別小心，會讓觸發動作卡在播放狀態、**永遠播不完，回不去平常的定格姿勢**，不確定要不要這個效果就不要填 `0`。

## 🎬 三種播放模式怎麼選

| 模式 | 怎麼開 | 行為 | 使用時機 |
|---|---|---|---|
| **單幀定格** | 什麼都不設（預設） | 取 `animation`（陣列則取第一個字串）在 `animationTime` 秒的姿勢，取樣成**一份固定形狀**，之後不再變 | 大多數情況的預設站姿 |
| **動畫粒子化** | `animatedIdle: true` + `animation` | 粒子形狀跟著 `animation` 指定的段落**一直循環播放**；`animation` 是陣列時，依序接成一條連續序列，播完自動跳回第一段 | 想要角色一直有動作感的展示模型 |
| **定時動作** | `particle.periodicAnimation` | 平常維持定格姿勢，閒置滿 `intervalSeconds` 秒觸發播一次 `periodicAnimation.name`，播完自動退回定格姿勢，不循環 | 想要平常安靜、偶爾才有一個「彩蛋動作」的模型 |

> [!WARNING]
> **`animatedIdle` 跟 `periodicAnimation` 不能同時開。** 兩者共用同一組 shader uniform（`uTextureModelA/B`／`uAnimBlend`），一個模型應該只用其中一種——同時開的話兩邊會搶著寫同一組 uniform，畫面會忽動忽靜。想同時測試兩者效果沒問題，但確認要哪個之後記得拿掉另一個。

## 🧮 關鍵幀數量自動計算

`animationFrames`（或 `periodicAnimation.frameCount`）不填的話，`particle-sampler.js` 的 `sampleModelAnimationFrames()` 會依這條序列的**總秒數**自動算一個值，不是固定的某個數字：

```
自動張數 = clamp(round(總秒數 × 3), 8, 64)
           目標密度：每秒 3 張（ANIM_AUTO_FPS）
           下限：8 張（MIN_ANIM_AUTO_FRAMES）——再短的動畫也不會少於這個數
           上限：64 張（MAX_ANIM_AUTO_FRAMES）——再長的動畫也不會超過這個數
```

**這三個數字的來源**：從幾個手動校正過的案例回推的經驗值，不是理論算出來的最佳值——

| 案例 | 秒數 | 舊寫死的 24 張換算密度 | 人工判斷 |
|---|---|---|---|
| `yasuoModel` 的 `Spell4` | 1.97s | 每秒 12 張 | 明顯過剩（現在自動算＝8 張，觸底） |
| `aatroxModel` 的 `Recall` | 8.67s | 每秒 2.8 張 | 「夠平滑」（現在自動算＝26 張，每秒 3 張） |
| `kaidoDragonModel` 的 `skill_e_1` | 25s | 每秒不到 1 張 | 「會比較跳」，手動拉到 48 張才解決（現在自動算＝64 張，觸頂） |

新公式在這三個已知案例上都落在「人工判斷覺得沒問題」的區間附近，換模型时不用再重複這套判斷。

> [!NOTE]
> 這條公式**只看得到秒數，看不到動作本身快不快、動幅大不大**——同樣是 3 秒，一段緩慢待機搖擺跟一段快速揮劍攻擊，需要的取樣密度天差地遠（快速大動作，幀數不夠會讓內插的粒子飄出一條軌跡而不是俐落的揮動）。自動算出來的數字只是一個安全的起點，播起來還是不夠平滑（或反過來想省 GPU 記憶體/載入時間），直接填 `animationFrames`/`frameCount` 手動覆寫即可，程式一律優先用你填的數字，不會被自動計算蓋掉。

## 🧮 關鍵幀分配公式

`animation` 是陣列（多段動畫接續播放）時，`animationFrames`（或 `periodicAnimation.frameCount`，不管是手動填的還是上一節自動算出來的）代表**整條序列**的關鍵幀總預算，不是每段各自這麼多張。分配邏輯在 `particle-sampler.js` 的 `sampleModelAnimationFrames()` 裡：

```
totalDuration = 所有段落秒數加總（各段 duration 直接讀 GLB 動畫本身的長度）
frameCount    = animationFrames（不填預設 24）

對第 i 段（不是最後一段）：
  frames_i = max(1, round(frameCount × duration_i / totalDuration))

對最後一段：
  frames_last = max(1, frameCount − 前面所有段落已分配的張數加總)
```

**重點：**

1. 每段依「自己時長佔總時長的比例」分配，時長越長分到越多張，接起來播放的節奏才會跟原始動畫一致（不會出現短動畫被放慢、長動畫被加速的錯覺）。
2. 最後一段不用比例算，是拿「總預算減掉前面已分配的」當剩下的份額——避免四捨五入誤差累積讓總數兜不起來。
3. 每段至少保底 **1 張**（`Math.max(1, …)`）。段數多、`frameCount` 又設太小時，保底張數是**額外加的**，不是從別段搶來的——代表**實際烘出的總張數可能會超過你填的 `animationFrames`**。

### 例子

`animationFrames: 24`，`animation: ['Idle1', 'Passive_Attack2', 'Recall']`，秒數分別是 2s / 5s / 8s（`totalDuration = 15s`）：

| 段落 | 秒數 | 算法 | 分到的幀數 |
|---|---|---|---|
| Idle1（第 1 段） | 2s | `round(24 × 2/15)` = `round(3.2)` | 3 |
| Passive_Attack2（第 2 段） | 5s | `round(24 × 5/15)` = `round(8)` | 8 |
| Recall（最後一段） | 8s | `24 − (3+8)` | **13** |

加總 3+8+13 = 24，剛好等於 `animationFrames`。

### 段數很多時要注意什麼

如果段數接近甚至超過 `animationFrames`（例如 90 幾段動畫、`animationFrames` 還是預設 24），平均每段連 1 張都分不到——幾乎每段都會被保底撐到 1 張，**實際烘出的總張數會遠超過你填的數字**，載入時間／GPU 記憶體跟著爆增，而且大部分段落只有 1 張代表畫面（整段動作只剩一個定格姿勢），動作會非常跳。這種情況建議：

- 把 `animationFrames` 拉高到至少段數的數倍，或
- 減少 `animation` 陣列裡實際要接續播放的段數（只留真的需要循環播放的幾段）。

## 🐢 銜接處變慢怎麼排查

多段動畫接起來播，銜接處（前一段收尾姿勢 → 下一段起始姿勢）容易感覺「動作變慢/變滑」，原因跟播放機制的兩個特性有關：

1. **只有兩張已烘好的關鍵幀之間做直線內插**（GPU `mix()`，見 `particle-effect.js` 的 `advanceAnimationPlayback()`），沒有真正的骨骼中間過渡。幀密度（`animationFrames` 相對 `totalDuration` 夠不夠高）越低，两幀之間間隔的時間越長，直線滑動的觀感就越明顯。
2. **`currentAnimClipDuration`（整條循環的總秒數）＝所有段落原始動畫真實秒數加總**。多接一段時長不短的動畫進陣列，整條循環的總秒數會被拉長，循環一輪要花更久，也會讓人覺得「變慢」。

### 排查順序

1. **確認陣列裡每一段是不是都是刻意要接的**——尤其檢查有沒有殘留的佔位符動畫（早期版本常見寫法是先填一個佔位字串、等升級成 `animatedIdle` 才補真的動畫標籤，升級後如果忘記檢查，佔位符會被真的接進循環播放）。
2. 檢查相鄰兩段的收尾/起始姿勢差異大不大；差異越大，銜接處的直線內插越明顯突兀。
3. 依〈關鍵幀分配公式〉檢查 `animationFrames` 相對 `totalDuration`／段數是否足夠，不夠就拉高。
4. 想精準定位，可以暫時在 `loadModelTexture()` 印出 `result.clipDuration`（即 `currentAnimClipDuration`），確認總循環秒數是否真的被某一段拉得很長。

## 🎮 手動微調 debug 工具

想校正某個模型的 `position`/`rotationY`/`scale` 又不想「改數字 → 重載 → 看效果 → 再改數字」一輪一輪試，可以用 `particle-effect.js` 內建的鍵盤微調工具：

1. `npm start` 跑起來，`F9` 切到互動模式。
2. `Ctrl+Shift+I` 開 DevTools，切到 Console 分頁（訊息也會同步印到 `npm start` 那個終端機視窗）。
3. 系統匣「光粒子特效」子選單選到要校正的模型。
4. 滑鼠在畫面上拖曳（進入 OrbitControls 拖曳狀態時，閒置動畫會暫停，微調結果不會被 `idleMotion` 蓋掉，見下面的注意事項），同時用鍵盤微調：

| 按鍵 | 作用 |
|---|---|
| `←` / `→` | `position.x` `-`/`+` 一個步距 |
| `↑` / `↓` | `position.y` `+`/`-` 一個步距 |
| `[` / `]` | `position.z` `-`/`+` 一個步距（不在方向鍵上，借中括號代表「深度」） |
| `Page Up` / `Page Down` | `rotationY` `+`/`-` 一個步距（按住等於連續轉，見下面〈能不能轉滿 360 度〉） |
| `End` / `Home` | `scale` 放大 / 縮小一個倍率 |
| 按住 `Shift` | 上面幾個都改用比較小的幅度，收尾精修用 |
| `R` | 全部歸零（含 scale），重新開始微調 |
| `P` | 不改變數值，只是重印一次目前的累計狀態 |

> [!IMPORTANT]
> **全部刻意選「非印刷字元」的功能鍵**（方向鍵／中括號／`Page Up`／`Page Down`／`Home`／`End`），沒有用逗號句號、加減號這類標點符號鍵——中文輸入法開著、標點設成全形時，這類鍵送到瀏覽器前會先被轉成全形標點（，。＋－），程式判斷的是半形字元，會直接「看起來沒反應」。上面這幾顆鍵不會被任何輸入法攔截。
>
> **滑鼠拖曳/滾輪不算在內。** 拖曳轉視角、滾輪縮放動的是 OrbitControls 的**相機**（跟原點的距離/角度），不是模型本身的 `position`/`rotation`/`scale`，這個工具完全不會追蹤、也追蹤不到——只有上面表格列的按鍵才會真的改到模型、並且印出數字。如果按了鍵盤卻沒印出對應的行（只看到 `P` 那種「沒改變，只是重印」），通常是鍵盤焦點不在桌寵視窗上（例如剛點過 DevTools 視窗），點回桌寵畫面再試。

### 能不能轉滿 360 度

可以。`rotationY` 沒有上限也沒有 wrap-around，一直按（或按住不放，瀏覽器鍵盤自動連發會持續觸發 `Page Up`/`Page Down`）就會持續累加，繞過一整圈（`2π ≈ 6.283`）之後還能繼續轉下去，沒有卡住的問題——只是每次印出來的 log 也會跟著洗版，想看某個角度時記得按 `P` 重印一次目前的準確數字。

每按一次都會在 Console／終端機印一行，例如：

```
[particle-debug] "virgoModel" position.x +0.05 → 累計偏移 position: [0.050, 0.000, 0.000]，rotationY: 0.000，scale 倍率: 1.000
  目前 sources.js 生效的參考值：position: [0, -1.43, 0]，rotationY: 3.142，scale: [1.1, 1.1, 1.1]
  要填回 sources.js 的數字＝ position/rotationY：參考值 + 累計偏移（相加）；scale：參考值 × 累計倍率（相乘，不是相加）
```

> [!WARNING]
> **`position`/`rotationY` 跟 `scale` 的算法不一樣，不要用同一套邏輯套用：**
> - `position`/`rotationY` 是**加法**性質：最終要填的數字＝**原本的值 + 這裡印出來的累計偏移**（照軸相加）。
> - `scale` 是**乘法**性質（`sources.js` 的 `scale` 本來就是拿去乘表面頂點座標，見 `particle-sampler.js` 的 `placed.scale()`）：最終要填的數字＝**原本的值 × 這裡印出來的累計倍率**（照軸相乘，不是相加）。
>
> 如果原本沒填 `position`/`scale`（auto-fit），參考值那行會提醒你去看模型載入時 `particle-sampler.js` 印的那行自動置中 log，用那組數字當基準再套上面的公式。

> [!NOTE]
> 這是純畫面上的即時微調，**不會寫回 `sources.js`**，換模型、重載、關閉桌寵都會消失，看到滿意的數字要自己手動抄過去。
>
> 只要有按過任何一個微調鍵（還沒按 `R` 歸零），這個模型的閒置動畫（`spin`/`bob`/`swing`）會自動暫停，畫面才會穩定顯示你調的結果——不然像 `swing` 那種每幀直接覆蓋 `rotation`/`position` 某一軸的閒置動畫，會把手動調的結果立刻蓋掉，看起來像沒反應。按 `R` 全部歸零後閒置動畫會自動恢復，不用手動再做什麼、也不用刻意按住滑鼠拖曳。

## 🩹 疑難排解

| 現象 | 常見原因 |
|---|---|
| Console 印 `animatedIdle 開了但沒填 animation` | `animatedIdle: true` 但 `animation` 沒填或是空陣列 |
| Console 印 `找不到動畫 "xxx"` | 動畫標籤名稱打錯，或這顆 GLB 根本沒有這段動畫（錯誤訊息會附上這顆模型全部可用動畫標籤，照著改） |
| Console 印 `animatedIdle 取樣失敗...改走單幀定格` | `sampleModelAnimationFrames()` 失敗，自動退回單幀定格路徑，不會讓整個模型讀取失敗，但代表 `animatedIdle` 沒真的生效，要往上找更早的 error log |
| 模型完全不顯示／飄到畫面外 | 通常是手動填的 `scale`/`position` 對不上這顆模型的實際包圍盒（例如換了 `file` 但沒重新校正），改成不填交給 auto-fit，或重新量測 |
| 銜接處動作忽然跳一下 | 見〈銜接處變慢怎麼排查〉，通常是幀密度不夠或姿勢反差太大 |
| 想同時用 `animatedIdle` 又想要閒置觸發的彩蛋動作 | 目前架構不支援，兩者共用同一組 uniform，只能擇一（見〈三種播放模式怎麼選〉的警告） |

> [!NOTE]
> `animationFrames`/`periodicAnimation.frameCount` 不填時**不是**固定常數，是依總秒數動態算出來的——公式跟 `ANIM_AUTO_FPS`（`3`）/`MIN_ANIM_AUTO_FRAMES`（`8`）/`MAX_ANIM_AUTO_FRAMES`（`64`）這三個常數（定義在 `particle-sampler.js` 開頭，不是 `particle-effect.js`）見〈關鍵幀數量自動計算〉。`animationSpeed`/`periodicAnimation.speed` 沒有對應常數，程式碼裡直接寫字面值 `1`（意義是「跟原始動畫真實秒數一致」，不是額外定義出來的參數）。
